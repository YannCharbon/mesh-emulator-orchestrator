# Virtual-time runs (EM3)

Scripts for the step-1 gate of `docs/VIRTUAL_TIME.md` (§7). They need a virtual-time build (§2): `wssimserver`, `wsbrd-inproc` and `wsnode-inproc` from `build-vt/`. `<workdir>` is the directory that holds `examples/` (the repo root).

Radio medium: since EM4, `wssimserver --vtime` runs the central medium by default (`docs/MEDIUM.md`: the server decides reception, collisions and CCA energy). `SIM_OPTS=--medium=legacy` gives a run the per-radio behaviour of the permanent reference runs; `nonreg_dag_simple.sh` passes it, and `medium_lfn_suite.sh` runs the LFN suite with it.

Analysis: `sim_utils/migration/analyze.py` reads these runs as it reads the wall-clock ones (`brtree` lines of `br.log` instead of `dbus_nodes.txt`). A border router that parents LFNs also logs its LFN children every 30 s as `brlfn` lines (EUI-64, listen interval, seconds since last heard, state), the content of the D-Bus property `LfnChildren` of the wall-clock programs.

```bash

# one dag_simple run, 300 virtual seconds, seed 3
WSSIM_SEED=3 TUN=tunvt0 sim_utils/vtime/run.sh $B $W runs/vt/seed3 300
python3 sim_utils/migration/analyze.py runs/vt/seed*      # -- runs/inproc/seed* to compare groups
# determinism: seed 1 twice (a, b) and seed 2 (c), under setarch -R
TUN=tunvt0 sim_utils/vtime/determinism.sh $B $W runs/vt/det 300 1
# speed at 15 (dag_simple), 100 and 500 nodes, 60 virtual seconds each
TUN=tunvt0 sim_utils/vtime/speed.sh $B $W runs/vt/speed 60 15 100 500
python3 sim_utils/vtime/gen_topology.py 500 --seed 2 -o topo500.txt   # then TOPO=topo500.txt run.sh ...
```

## run.sh

Power recording (EM2, `docs/POWER_MODEL.md`): `POWER=examples/power/efr32fg25-soc.ini` adds `power.json` to the run (`POWER_LOG=1`: also `power_log.txt`, every state interval; `POWER_CELL=mAh[:V[:eff]]`: battery life; `POWER_OPTS="--power-mode=3"`: whose profile values apply, by default the PHY mode the node runs, `docs/POWER_MODEL.md` §6.2). `campaign.sh` passes these through; `sim_utils/power_summary.py runs/...` summarises the runs. In `POWER_OPTS` and `SIM_OPTS`, the files the server reads (`--power`, `--power-node=IDS:PROFILE`, `--group-file`) are relative to the directory `run.sh` is called from, as `POWER` and `TOPO`, and must exist; the files it writes (`--medium-log`, `--sniff-log`, `--power-out`, `--power-log`, `--vtime-frames`) are relative to the output directory. When the server fails, `run.sh` prints the end of `simserver.log`. `SOCK` is at most 107 bytes (the limit of a UNIX socket path).

Output: one log per program (`simserver.log`, `br.log`, `node<i>.log`), with no timestamping wrapper: the simulation port starts every line with `NSIM_EPOCH_S` + virtual time, and `t0` holds `NSIM_EPOCH_S` (1700000000). Also `topology.txt`, `run_info.txt` (seed, socket, wall-clock start and end), `exit_codes.txt`, `log_wsbr` and `storage/`.

The run ends when `wssimserver` exits (`--vtime-end`, or SIGTERM from `WALL_TIMEOUT`). A program that exits with an error before that stops the run, and any program that exits with a non-zero status, at any time (an AddressSanitizer or leak report at exit included), makes `run.sh` fail, except the instances that `KILL` or `RESTART` stopped.

Node events (conductor options, `wssimserver --help`): `KILL="<i>:<s>"` stops node i outright at virtual second s (no more wakes or frames; its program then exits with "conductor closed the connection"); `RESTART="<i>:<s>"` starts a new instance of node i with the same options and key storage at s (the running one is stopped then), logging to `node<i>.r1.log`: its first run is at s and its clock starts at 0 then, as a device's at power-up (`docs/VIRTUAL_TIME.md` §3); `POWER_UP="<i>:<s>"` powers node i (its only instance) up at s instead of 0, and `SPREAD=<s>` with `SPREAD_NODES="<i> ..."` powers each of these nodes up at its own offset in [0, s), drawn from the seed and its ID (the LFN tests with several LFNs under one parent use it: LFNs started in the same µs send their LPAS sweeps in step, and with the central medium these collide); `CUT="<a>:<b>:<s>"`: from s, frames from a no longer reach b; `LINK="<a>:<b>:<s>:<rssi>"`: from s, the link a–b has this RSSI; `DROP="<a>:<b>:<seq>:<s1>:<s2>"`: frames from a with MAC sequence number seq are not delivered to b between s1 and s2. `FRAMES=1` writes every frame sent to `frames.txt` (time in µs, sender, channel, PSDU in hex; `lfn_lib.frames()` reads the MAC header and the frame counter). `IF_NODES="<i> ..."` adds clients of the stack-neutral radio interface (`docs/RADIO_INTERFACE.md`) to the run: each runs `IF_CMD_<i>` (default `IF_CMD`) with `--sock <socket> --id <i>` and `IF_OPTS_<i>`, logging to `if<i>.log`; the programs run in the output directory, so a word of these that contains a `/` and names an existing file or directory relative to the directory `run.sh` is called from is made absolute (`IF_CMD="python3 radio_if/ref_client.py"`, `IF_CMD=./my_client`), while a bare name is looked up on `PATH`; their IDs may appear in `TOPO` and are not routers (`radio_if/test_mixed.sh` uses it); with node 0 among them, the run has no Nanostack program at all (no border router, no routers) and every node of `TOPO` must be a client. `ref_client.py --mop-period-ms P` also prints the client's state, links, counters and events as `MOP1` lines, which the mesh testbed controller reads (line format: the first word is the virtual time in µs, then `MOP1 ` and one JSON object to the end of the line; `docs/RADIO_INTERFACE.md` §10, "Node logs"). With node 0 among the clients, `<workdir>` needs no `examples/` and the run writes no `examples`, `storage/` or `log_wsbr`. `DUMP=1|0` chooses whether `simserver.log` starts with the topology and RSSI matrices (default: only up to 200 nodes). `KILL` and `RESTART` cannot be combined with `POWER` (`POWER_UP` and `SPREAD` can: the node's ledger starts at its power-up, and its averages and sum check are over its own time, from its `start_us`). Test traffic (`app_wsbrd/test_traffic.c`) also has `test_udp_at_s` (one request to each destination at these times, repeatable), `test_udp_gap_ms` (the destinations of a round that far apart), `test_udp_listen` (log what arrives, answer nothing), and up to 64 `test_udp_dst`. The script never uses `pkill`; it stops only the processes it started. Options are environment variables, listed at the top of the script: `WSSIM_SEED`, `TOPO`, `SOCK`, `TUN`, `SETARCH=1`, `KEEP_DBUS=1`, `WALL_TIMEOUT`, `RSS=1`, `CONF` (`CONF=eu1a`: `examples/wsbrd-eu1a.conf` and `wsnode-eu1a.conf`, the FG25 firmware's PHY), `BR_OPTS`, `NODE_OPTS`, `NODE_OPTS_<i>`, `BR_ENV`, `NODE_ENV_<i>` (environment for one program), and the `POWER*` options. The programs inherit the environment, so `WSSIM_RADIO_OFF=0` (the emulated radio's `PHY_INTERFACE_DOWN` leaves RX on, as before GS8 stage 1) and the `WSSIM_PHY_*` settings (data rate and PHY overhead, `docs/POWER_MODEL.md` §6.1) apply to a whole run or campaign; `NODE_ENV_<i>` sets them for one node.

## Topology files

`TOPO=<file>` (`run.sh`) and `wssimserver --group-file=<file>` read the same format: one `wssimserver -g` argument per line.

| Line | Meaning |
| --- | --- |
| `A,B:RSSI` | the link A → B at RSSI dBm (the power at B of A's frames); also B → A unless the file has a line `B,A:RSSI` |
| `A,B` | a link at 0 dBm (a perfect link; it destroys any frame it overlaps) |
| `A-B:RSSI`, `A,B,C:RSSI` | every pair of these nodes, both directions |
| `-g A,B:RSSI`, `--group=A,B:RSSI` | the same: a leading `-g` or `--group=` is accepted |
| blank, or `#` to the end of the line | skipped |

Lines apply in order and a later line wins; the server warns in `simserver.log` when a line changes a value an earlier one set, and counts the asymmetric links (`docs/MEDIUM.md` §2). A malformed line stops the server with the file name and line number. `run.sh` writes the cleaned file to `<outdir>/topology.txt` and gives it to the server with `--group-file` (before 2026-11-09 it passed each line as `-g`, which took minutes and was limited by the command line's length above about 2000 nodes); it also refuses lines with spaces inside. For `run.sh`, node 0 is the border router and the routers are 1 to the highest ID that is not in `IF_NODES`.

```
# 4 nodes: 0-1 and 1-2 the same both ways, 2-3 asymmetric
0,1:-62.5
1,2:-70     # a comment
2,3:-75
3,2:-81     # node 2 hears node 3 at -81 dBm, node 3 hears node 2 at -75
```

Generators: `gen_topology.py` (random geometric graph, grid or star, from a seed) and `radio_if/scale/gen_building.py` (a multi-floor building from a path-loss model, the topology of the scale runs: `docs/SCALE.md` §2) write this format, each link once.

## Running several runs at once

What each run gets of its own, and what it shares:

| Resource | Per run? | How |
| --- | --- | --- |
| Conductor socket | yes | `SOCK`, default a new `/tmp/wssim-vt-*.sock` |
| Shared memory (CCA, node infos) | yes | named from the socket path (`sim_shm_name()`, §3) |
| Key storage (`*_pae_*`, the BR's PAN ID) | yes | `storage_prefix=storage/<node>_`, relative to the run directory |
| BR trace file (`/tmp/log_wsbr`) | yes | `WSBRD_LOG_FILE=<run>/log_wsbr` |
| D-Bus names (`com.silabs.Wisun.BorderRouter`, `com.wshwsim.mac*`) | not shared | the programs cannot reach D-Bus (`KEEP_DBUS=1` to allow it). They register with `REPLACE_EXISTING`, so otherwise a run would take the names of another run, including a wall-clock run's |
| **TUN device** | **no** (`TUN=none`: not used) | `wsbrd-inproc` opens it with `TUNSETIFF`, which fails while another border router holds it. `TUN=none` runs the border router without a TUN device (no sudo; its IPv6 output goes nowhere, so the traffic must come from the programs themselves, `test_udp_*`), any number of runs at a time: the default of the LFN tests, `lfn_suite.sh` and `nonreg_dag_simple.sh`. The border router then takes the link-local address of the `tunvt` devices, so `dag_simple` logs match runs made on `tunvt0` once printed heap addresses are masked. For host traffic, give each concurrent run its own device: `sudo ip tuntap add mode tun user $USER name tunvt0 && sudo ip link set tunvt0 up`, then `TUN=tunvt0` (`run.sh`'s default is `tun0`). Use the same TUN for runs you compare byte for byte (the BR reads the TUN's link-local address) |
| Process names | **no** | `sim_utils/migration/headless_run.sh` runs `pkill -x wsbrd-inproc`, `wsnode-inproc` and `wssimserver`: it kills every run on the PC, virtual-time runs included |

`/tmp/wsbrd/` is not used by any program (`headless_run.sh` only creates it). The default `storage_prefix` of the programs is `/var/lib/wsbrd/`, shared by all runs, which is why `run.sh` always sets it.

## Campaigns: several runs at once

Each run uses about 1.4 CPU cores (the conductor and the one node it is running), so a PC runs many at once. Virtual time does not depend on the CPU load, so a run gives the same logs alone or in a campaign.

```bash
sudo sim_utils/vtime/tun_setup.sh 12        # once per boot: tunvt0..tunvt11
SETARCH=1 sim_utils/vtime/campaign.sh build-vt $(pwd) runs/vt/campaign 300 $(seq 1 12)
```

Measured on a 24-core PC (2026-10-27, `dag_simple`, 300 virtual seconds, 12 seeds): 48.0 s one at a time, 10.5 s six at a time, 7.0 s twelve at a time (6.8×). Every seed's logs were identical in the three cases, and identical to earlier runs on `tun0` (`compare_logs.py --mask-pointers`: only printed heap addresses depend on the TUN's name).

**Memory.** A run needs about 5 MB per node (measured: 71 MB at 15 nodes, 0.5 GB at 100, 2.5 GB at 500), so a campaign needs about `JOBS` times that. Before starting, `campaign.sh` estimates it (5 MB per node plus 20%, `MB_PER_NODE`) and compares it with the available memory minus a reserve (`RESERVE_GB`, default 4). If `JOBS` runs do not fit, it lowers `JOBS` to what fits and prints why, for example `campaign: JOBS=12 needs ~36 GB, 24 GB usable: running 6 at a time (FORCE=1 to keep 12)`. If not even one run fits, it does not start. `FORCE=1` keeps `JOBS` as given. The check is made once, at the start, and the estimate is from `dag_simple` and generated topologies: denser networks may need more.

The `tunvt` devices carry no generated addresses and the same fixed link-local address, because `wsbrd` reads and logs it: with tun0's random address a run would log a different address on each device.
